# GUI Workflow

## English version

The GUI is a thin, responsive wrapper around the CLI. **Files** contains New, Open, Save, Save As, Close, Delete and Exit. A project must be open before build controls are enabled.

The project wizard selects an aircraft and general settings. The Geometry tab selects the build mode, object composition and editing rules; the Textures tab selects a geometry checkpoint, map replacements and texture search. The Journal tab contains detailed logs. After a successful stage, **Open in Blender** and **Show in Explorer** open the selected result. Back/Next buttons move between steps only when the minimum required fields are present.

The GUI uses automatically detected MSFS roots and multiple additional roots. **Package folders** lists automatic roots separately from user-added roots, marks missing custom paths, and lets users add or remove roots without editing JSON. Catalog, index, package diagnosis and model-selection commands receive the same configured root list.

---

Оконная оболочка `msfs_builder_gui.py` — тонкая обёртка над CLI. Blender запускается отдельным процессом, все долгие операции выполняются в фоне, интерфейс остаётся отзывчивым.

Окно 1120×760, минимум 920×640. Заголовок содержит версию. Сверху — «Сканировать MSFS», «Выбрать каталог», «Каталоги Packages…» и строка состояния. Снизу — «← Назад», подсказка и «Далее →».

## Меню

**Файлы:** Новый проект · Открыть проект… · Сохранить (Ctrl+S) · Сохранить как… · Закрыть проект · Удалить проект… · Выход.

Отдельно: **Пути и настройки…** (Blender и добавление каталога), **Каталоги Packages…** (автоматические корни MSFS, несколько вручную добавленных корней и управление ими), **Индекс пакетов…** (состав индекса, состояние баз, фильтр по имени, перестроение) и **Руководство**.

Автоматически найденные пути показаны отдельно от вручную добавленных. Можно добавить несколько библиотек или мод-каталогов; отсутствующий вручную добавленный путь отмечается и может быть удалён. Один и тот же список используется каталогом, индексом, диагностикой пакета и мастером моделей.

Пункты сохранения, закрытия и удаления активны только при открытом проекте.

## Вкладки

### «Проекты» (стартовый экран)

Видна только без открытого проекта: кнопки «Новый проект» и «Открыть проект…». При открытии проекта скрывается.

### «1. Самолёт»

Появляется только как первый шаг мастера, пока проект не открыт. Содержит:

- поле корня сканирования + «Обзор» + «Сканировать»;
- список самолётов с пометками `⚠ причина`, `◐ причина`, `⚠ карты не найдены`;
- строку состояния: сколько найдено, сколько полных, скольким нужен выбор моделей, сколько недоступно;
- строку причины с рекомендуемым действием, разрешённой базой и происхождением моделей;
- кнопку **«Проверить пакет подробно»** (`inventory --deep`);
- поле деталей — читаемый структурированный отчёт.

Выбор недоступного самолёта блокируется с объяснением. Выбор самолёта с пометкой `◐` открывает [мастер выбора моделей](Model-Selection): раздельные списки экстерьера и интерьера со всеми LOD, числом вершин и треугольников и состоянием BIN. Подтверждённый состав записывается в `models`, вариант сборки получает суффикс `_partial`. Подробности: [Package Diagnosis](Package-Diagnosis) и [Package Index](Package-Index).

### «2. Настройка»

Только **общие параметры проекта**. Режимы сборки сюда не входят.

| Поле | Поведение |
|---|---|
| Самолёт | только чтение |
| Model-вариант | выпадающий список; смена очищает явные `models` и дерево объектов |
| Ливрея | выпадающий список из `texture`/`texture.*` |
| Папка blend проекта | только чтение, `<проект>/blend` |
| Blender | редактируемое поле + «Обзор» |
| Указать новое расположение исходного самолёта… | перепривязка источника после переноса на другой ПК, с той же диагностикой и мастером выбора моделей |
| Состав моделей | строка с подтверждённым составом и кнопка **«Выбрать модели...»** — открывает [мастер](Model-Selection) повторно, в том числе после сборки |

Пока самолёт требует выбора моделей, а состав не подтверждён, сборка отклоняется с указанием на кнопку «Выбрать модели...».

Кнопка «Далее» активна только когда заполнены минимум: проект открыт, выбран самолёт, model, ливрея, каталог результатов и существующий `blender.exe`. Переход сохраняет проект и автоматически загружает список объектов.

### «3. Геометрия»

- **Состояние сборки:** этап, ход операции, итог, индикатор занятости (не процент).
- **Параметры:** `Skinning` (`strip`, `manual`, `hybrid`, `bake`), `Draw mode` (`auto`, `msfs`, `standard`), имя варианта, флажок «Удалять runtime/collision/occluder».
- **Дерево объектов** с колонкой «Включён» (☑/☐). Клик по объекту переключает его; клик по группе — все её объекты. Группа показывает ☐, если исключён хотя бы один дочерний объект. Кнопки: «Загрузить список объектов», «Включить всё», «Исключить всё», «Hybrid: выбранная деталь» + счётчик целей.
- **«Правила редактирования...»** — окно графических редакторов `split_by_skin`, `split_spatial`, `mirror_objects`, `placements`, `collection_overrides`, `manual_keep_pivots`. Рядом строка с числом заданных правил; без правил написано «Правила не заданы: объект собирается как есть». Подробности: [Rule Editors](Rule-Editors).
- **Действия:** «Собрать geometry», «Открыть checkpoint», «Перейти к .blend в Проводнике» (появляется после успешной сборки), «Остановить».

Подробный журнал сборки здесь не показывается — он на вкладке «Журнал».

### «4. Текстуры»

Визуально приближена к вкладке геометрии: то же «Состояние сборки».

- Флажок «Подключать все texture.* варианты».
- **«Таблица карт...»** — окно со всеми картами отчёта, их состоянием и заменой через `texture_overrides`; там же поиск недостающих карт по установленным пакетам. Подробности: [Rule Editors](Rule-Editors).
- Многострочное поле дополнительных каталогов текстур (по одному на строку).
- Список **«Собранные варианты для сравнения»** — все `*.blend`, отсортированы по номеру сборки в имени (по убыванию); файлы без номера идут последними. Время изменения используется только при равных номерах, поэтому копирование, распаковка или облачная синхронизация не выводят старый вариант наверх. Двойной клик открывает в Blender. Кнопки «Обновить список», «Открыть выбранный», «Показать в Проводнике».
- Действия: «Добавить textures», «Собрать final», «Весь цикл», «Открыть checkpoint», переход в Проводник, «Остановить».

Для `textures` нужен выбранный файл `01_geometry*.blend`, для `final` — `02_textured*.blend`. Состав моделей и имя варианта берутся из JSON-отчёта выбранного checkpoint, поэтому текстурирование соответствует именно той геометрии, которую вы проверили.

### «Журнал»

Только для чтения, с обеими полосами прокрутки и кнопкой «Сохранить журнал…» (экспорт в `.log`). Сюда попадают команды CLI, stdout и stderr.

## Порядок и ограничения

1. Работать вне проекта нельзя: вкладки 2–5 и операции с проектом заблокированы.
2. «Далее» активна только при заполненном минимуме параметров; «Назад» возвращает на предыдущий шаг.
3. Во время операции блокируются все кнопки, поля, списки и деревья на четырёх рабочих вкладках, кроме «Остановить». Второй запуск отклоняется.
4. Каждый запуск использует **отдельный снимок** конфигурации в `<проект>/work/run-<uuid>.json`, поэтому изменение настроек во время сборки не влияет на идущий процесс.
5. Остановка завершает дерево процессов, чтобы дочерний Blender не продолжал запись.
6. Код возврата `2` показывается как «Готово с замечаниями», а не как авария: файл создан и доступен.

## Жизненный цикл проекта

**Создание.** «Новый проект» → шаг «1. Самолёт» → выбор самолёта → «Далее» → диалог папки и имени. Создаётся `<папка>/<имя>/<имя>.json` и маркер `.msfs-project.json` с именем проекта и версией. Каталог не должен существовать и не должен лежать внутри пакета MSFS. По умолчанию предлагается `Documents\MSFS_Projects`. Диалоги выбора папки имеют кнопку **«Создать папку»**.

**Открытие.** «Файлы → Открыть проект». Читается JSON, восстанавливаются все поля, неизвестные ключи сохраняются в расширенных правилах. Фоном запускается `inventory`, чтобы обновить диагностику и списки вариантов.

**Сохранение.** Атомарная запись через временный файл и замену. Текущая рабочая вкладка не меняется. Несохранённые изменения отслеживаются.

**Удаление.** После отдельного подтверждения JSON и **принадлежащая проекту** подпапка `blend` переносятся в `%LOCALAPPDATA%\MSFSModelBuilder\DeletedProjects\<имя>-<hex10>\` вместе с `restore.json`, где хранятся исходные пути. Общие папки `blend` старых проектов не переносятся и не удаляются.

**Перенос на другой ПК.** Скопируйте папку проекта целиком, затем «Указать новое расположение исходного самолёта…» и проверьте путь к Blender. Упакованные изображения переносятся вместе с `.blend`; исходники нужны для повторной сборки.

## Где что лежит

```
<папка проекта>/
├── <имя>.json              конфиг проекта
├── .msfs-project.json      маркер владельца
├── work/
│   └── run-<uuid>.json     снимок конфигурации на запуск
└── blend/
    ├── 01_geometry_<variant>_<NNN>.blend
    ├── 01_geometry_<variant>_<NNN>.json
    ├── 02_textured_<variant>_<NNN>.blend / .json
    ├── 03_model_<variant>_<NNN>.blend / .json
    ├── <stage>-<run10>.plan.json
    ├── <stage>-<run10>.log
    ├── decoded_normals/
    └── .msfs_pipeline.lock  (временно)
```

Нумерация ведётся отдельно для каждой комбинации режимов и не ограничена тремя цифрами. Существующие файлы не перезаписываются.

## Графическое редактирование без JSON

| Инструмент | Где | Что пишет в конфиг |
|---|---|---|
| Включение/исключение объектов и групп | «3. Геометрия», дерево | `exclude_objects` (точные имена экранируются) |
| Цели hybrid | «3. Геометрия», кнопка | `hybrid_bake_objects` |
| Режимы и фильтрация runtime | «3. Геометрия» | `skinning`, `draw_mode`, `filter_runtime` |
| Дополнительные каталоги карт | «4. Текстуры» | `extra_texture_dirs` |
| Все ливреи в поиске | «4. Текстуры» | `include_all_liveries` |
| Выбор исходного checkpoint | «4. Текстуры», список | `--input-blend`, `models` и `build_variant` из отчёта |
| Состав моделей | «1. Самолёт» автоматически, «2. Настройка» кнопкой | `models`, суффикс `_partial` |
| Разделение по костям и по координатам, зеркальная копия, привязка к якорю, коллекция по шаблону, pivot для manual | «3. Геометрия» → «Правила редактирования...» | `split_by_skin`, `split_spatial`, `mirror_objects`, `placements`, `collection_overrides`, `manual_keep_pivots` |
| Замена карты и поиск недостающих изображений | «4. Текстуры» → «Таблица карт...» | `texture_overrides`, дополнение `extra_texture_dirs` |

Все правила проверяются до запуска Blender: сначала в форме, затем командой CLI `validate`, которая использует ту же функцию `validate_config`, что и конвейер. Отказ показывается текстом ошибки, форма остаётся открытой. Подробнее: [Rule Editors](Rule-Editors).

**Без графического редактора** остаётся расширенный ключ `profile`. `normal_decode` (`auto`, `dxt5n`, `off`) и каталог готовых PNG `converted_normal_dir` выбираются на вкладке «Текстуры», а `pose_position` и `repair_skin_roots` — в параметрах geometry. Остальные ключи движок поддерживает, GUI сохраняет при круговой загрузке, но задаются они в JSON.
