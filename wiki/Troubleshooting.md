# Troubleshooting

## English version

Use this order: diagnose the package, verify the selected geometry, then investigate textures.

If the aircraft is absent, set the MSFS/package root and rescan. If it is partial, inspect the base package and confirm models in the wizard. If geometry is displaced, compare another mode and use a placement/mirror rule. If a texture is missing, search installed package roots and inspect the map table. For `KHR_draco_mesh_compression` or `EXT_meshopt_compression`, choose another LOD or decompress the source in its exporter; build modes cannot decode compressed geometry. A missing original glTF/BIN cannot be fixed by changing a build mode. Keep the detailed Journal log and the failed checkpoint when reporting a reproducible problem.

---

Порядок диагностики всегда один: **сначала причина пакета, потом геометрия, потом карты**. Не меняйте режим сборки, пока не убедились, что выбран правильный состав моделей.

## Самолёт не появился в списке или помечен причиной

| Что видно | Причина | Действие |
|---|---|---|
| список пуст | не найден `UserCfg.opt` или `InstalledPackagesPath` | «Пути и настройки» → укажите каталог `Packages`, `Official`, `Community` или папку распакованного мода и запустите «Выбрать каталог» |
| `◐ SUPPORTED_PARTIAL` | часть объявленных моделей недоступна | «Проверить пакет подробно»: строка «Базовый самолёт» называет точную причину (см. ниже) |
| `◐ SUPPORTED_PARTIAL`, «базовый самолёт не установлен» | ливрея наследует модель пакета, которого нет в установке | установите базовый самолёт либо добавьте его корень через «Пути и настройки» и пересканируйте |
| `◐ SUPPORTED_PARTIAL`, «базовый самолёт установлен, но объявленный файл в нём отсутствует» | база есть, но объявленного XML в ней нет (например, интерьер поставляется как glTF LOD01+) | откройте [мастер выбора](Model-Selection): он обходит базовый пакет и показывает найденный там файл. Автоматической подстановки нет — строку с источником роли «имя файла» включает пользователь |
| `◐ SUPPORTED_PARTIAL`, «несколько установленных пакетов» | имя самолёта встречается в нескольких пакетах | посмотрите кандидатов в деталях и укажите нужный корень; программа не угадывает |
| `⚠ COMMON_RESOURCES_ONLY` | в пакете только общие XML/текстуры/звуки | найдите пакет самого самолёта; общие пакеты не собираются отдельно |
| `⚠ LIVERY_ONLY` | есть `aircraft.cfg` и карты, но нет `model` | укажите базовый самолёт или добавьте корень, где он лежит |
| `⚠ MISSING_MODEL_CFG` / `INVALID_MODEL_CFG` | нет cfg или нет секции `[models]` | подробная проверка предложит найденные LOD glTF; подтвердите назначение вручную |
| `⚠ MISSING_BUFFER` | рядом с glTF нет BIN | восстановите пакет; один glTF без BIN собрать нельзя |
| `⚠ UNSUPPORTED_GLTF_FEATURE` | Draco/Meshopt-сжатие (`KHR_draco_mesh_compression`, `EXT_meshopt_compression`), KTX2 и другие неподдерживаемые расширения либо primitive points/lines | выберите другой LOD или распакуйте геометрию в экспортёре; режимы сборки не декодируют сжатую геометрию. GLB, несколько buffers, data URI и triangle strip/fan поддерживаются |
| `⚠ UNREADABLE_GLTF` | JSON повреждён или недоступен | проверьте права и целостность пакета |
| `⚠ UNRESOLVED_ALIAS` | `base_container` указывает на отсутствующий пакет | установите базовый самолёт либо добавьте его корень в «Дополнительные корни» |
| `⚠ SCAN_FAILED` | структура пакета отличается от ожидаемой | откройте детали, укажите папку конкретного самолёта |
| `⚠ карты не найдены` | геометрия есть, изображений нет | геометрию собрать можно; текстуры добавите позже |

Подробности кодов: [Package Diagnosis](Package-Diagnosis).

## Сборка не запускается

| Симптом | Проверка |
|---|---|
| «Укажите blender.exe» | путь должен вести на существующий `blender.exe`, а не на папку; запустите Blender один раз вручную |
| кнопка «Собрать geometry» неактивна | идёт другая операция: на время сборки блокируются все кнопки, поля и списки рабочих вкладок, кроме «Остановить». Дождитесь итога в строке статуса |
| «Нажмите «Выбрать модели...» на шаге 2 и подтвердите состав» | самолёт требует выбора состава, а мастер не подтверждён. Откройте [мастер](Model-Selection), отметьте хотя бы один доступный файл и подтвердите; отказ происходит до запуска Blender |
| «Проект не открыт» | вкладки сборки доступны только внутри проекта: «Файлы → Новый проект» / «Открыть проект» |
| «Другая операция уже выполняется» | дождитесь итога в строке статуса; второй фоновый процесс намеренно запрещён |
| «Проект занят другой сборкой» | остался `*.lock`; программа снимает устаревшую блокировку сама, живую уважает — не удаляйте файл вручную во время работы |
| ошибка выбора моделей до запуска Blender | это `selection_diagnosis`: прочитайте блок «Диагностика пакета», он объясняет, какой ресурс отсутствует |
| «не содержит extras.ASOBO_primitive» при `draw_mode=msfs` | файл — обычный glTF, а не упакованный MSFS; верните `auto`, он выбирает чтение по содержимому каждого primitive |

## Геометрия собралась, но детали не на месте

Это самый частый класс проблем. Действуйте по шагам, меняя **один** параметр за сборку, и сравнивайте numbered checkpoints.

1. Убедитесь, что выбраны правильные модели: exterior и interior не перепутаны, LOD00 не подменён другим LOD.
2. Соберите `strip` + `auto` — базовый вариант.
3. Если отдельные узлы смещены или развёрнуты, попробуйте `manual`: он сохраняет POSITION в системе координат самолёта и убирает pivot узла.
4. Если деформация зависит от костей, попробуйте `bake`: статическое положение вычисляется через armature Blender.
5. `hybrid` применяйте точечно: выберите только проблемные объекты. Он требует одинакового числа вершин и полигонов.
6. При разорванных поверхностях сравните `draw_mode`: `standard` и `msfs`. `auto` выбирает MSFS-диапазоны только там, где они действительно есть в `extras`.

Что **не** помогает при смещении: смена ливреи, `normal_decode`, повторная сборка того же режима.

Зеркалирование и точечное размещение исправлены на этапе B: `mirror_objects` отражает относительно мировой плоскости симметрии, переносит начало координат, пересчитывает UV и пользовательские нормали; `placements` наследует только положение якоря. Прежние ограничения и остальные известные случаи описаны в [Known Issues](Known-Issues).

## Лишние или отсутствующие объекты

- Лишние: снимите галочку группы или объекта в дереве и пересоберите геометрию. Исключения попадают в `exclude_objects` автоматически.
- Не исключайте служебные родительские узлы вслепую — вместе с ними исчезнут дочерние детали.
- В дереве нет нужного объекта: нажмите «Загрузить список объектов»; список читается из фактического `.blend`, а не из glTF.
- Ожидаемая деталь отсутствует и в `.blend`: скорее всего она не входит в подтверждённый состав моделей. Проверьте диагностику пакета.

## Правила редактирования

| Симптом | Действие |
|---|---|
| «Правило отклонено» с текстом вида `split_spatial/1: границы cuts должны идти по возрастанию` | это ответ команды `validate`, то есть проверка до запуска Blender. Исправьте указанное поле в форме и сохраните снова; сборку запускать не нужно |
| «В загруженном списке объектов нет имён: …» | нажмите «Прочитать объекты из checkpoint» и выберите имя из списка. Blender мог добавить суффикс `.001`; предупреждение можно подтвердить, но правило с несуществующим именем остановит сборку |
| в списке костей пусто или «в файле нет skin-узлов» | объект не скинованный: разделяйте его по координатам. Кости читаются из документа `.gltf` или JSON-части `.glb` без BIN; проверьте, что выбран исходный файл с `nodes`/`skins` |
| «Границы неизвестны» в форме разделения | границы берутся из фактического checkpoint: нажмите «Прочитать объекты из checkpoint». До первой сборки их нет, и «Предложить границы» ничего не предложит |
| кость показана серым и не выбирается | она уже назначена другой части. Одна кость принадлежит ровно одной части; перенесите её, удалив из прежней части |
| правило сохранено, но сборка его не применила | правила действуют на **следующую** сборку. Сохраните проект (Ctrl+S) и запустите «Собрать geometry» или «Весь цикл» заново |
| часть или остаток оказались пустыми | конвейер отклоняет такое разделение. Сдвиньте границу или перераспределите кости: и каждая часть, и остаток должны содержать грани |

Подробнее: [Rule Editors](Rule-Editors) · [Object Organization](Object-Organization).

## Текстуры

| Симптом | Действие |
|---|---|
| поверхности белые/серые | включите Material Preview; в обычном Solid материалы не видны |
| часть карт не найдена | откройте «Таблица карт...»: строки с проблемами идут первыми. «Найти в установленных пакетах» ищет карту по всем корням, «Заменить...» подставляет свой файл, «Добавить найденные папки в поиск» дописывает каталоги в поиск |
| таблица карт пуста и просит выполнить сборку | отчёта текстур ещё нет: запустите «Добавить textures» или «Весь цикл». Итоговый `03_model*.json` карт не содержит, программа берёт `02_textured*.json` той же сборки |
| замена карты не применилась | замена действует на следующем этапе `textures`; ключом служит имя карты из glTF, а не имя нового файла — таблица записывает его сама. Проверьте состояние «заменена вручную» и пересоберите текстуры |
| карты взяты не из той ливреи | отключите «Подключать все `texture.*» и оставьте выбранную ливрею со штатными fallback |
| металличность/шероховатость неверны | проверьте COMP: R — occlusion, G — roughness, B — metallic |
| нормали «вывернуты» | проверьте `normal_decode`; для NORM зелёный канал инвертируется (DirectX → OpenGL) |
| DXT5-нормали остались сжатых артефактов | `normal_decode=dxt5n` вместо `auto` (`auto` распаковывает только BC5S/BC5U) |
| приборы и дисплеи пустые | их рисует симулятор во время работы; готовой карты в пакете нет |
| `missing_fallback_dirs` в отчёте | нормально: MSFS объединяет пакеты в VFS, и `texture.cfg` часто ссылается наружу; диагностика такие ссылки разрешает через индекс |

Подробнее: [Textures and Materials](Textures-and-Materials).

## Индекс пакетов

| Симптом | Действие |
|---|---|
| ливрея частичная, хотя базовый самолёт установлен | откройте «Выбрать модели...»: мастер просматривает базовый пакет и показывает его файлы с происхождением «из пакета базового самолёта». Если нужной роли нет и там, откройте «Индекс пакетов…» и проверьте пометку базы: «НЕ установлена» означает, что индекс не нашёл самолёт с таким именем ни в одном корне |
| база установлена, но помечена «НЕ установлена» | имя в `base_container` отличается от имени папки самолёта, либо пакет лежит в корне, который не сканируется. Добавьте корень через «Пути и настройки» и нажмите «Перестроить индекс» |
| после установки нового пакета список не изменился | «Индекс пакетов…» → «Перестроить индекс». Кэш инвалидируется по mtime каталога `SimObjects/Airplanes` и конфигов пакета; распаковка поверх старого каталога может сохранить mtime |
| в журнале «Индекс: каталог недоступен» | указанный корень не существует или недоступен. Остальные корни продолжают сканироваться; исправьте путь в «Пути и настройки» |
| скан стал медленнее после правки настроек | изменился список корней, поэтому кэш не подошёл и индекс перестроился заново. Следующий скан снова возьдёт записи из кэша |
| модель взята «не из того пакета» | в подробной диагностике у модели указан каталог-источник. При нескольких кандидатах программа сообщает неоднозначность и не выбирает сама |

## Файлы, проекты, переносимость

- Каждый запуск создаёт **новый** файл; счётчик отдельный для каждой комбинации режимов. Старые checkpoints не перезаписываются.
- Все `.blend` лежат в подпапке `blend` рядом с JSON проекта.
- Не размещайте проект внутри пакета MSFS: созданные файлы попадут в список самолётов симулятора.
- Перенос проекта на другой ПК: скопируйте папку проекта целиком, затем «Перепривязать исходный самолёт» и проверьте путь к Blender. Упакованные изображения уедут вместе с финальным `.blend`; исходники нужны только для повторной сборки.
- Удаление проекта переносит его в `%LOCALAPPDATA%\MSFSModelBuilder\DeletedProjects` вместе с собственной подпапкой `blend`; `restore.json` хранит исходные пути.
- Portable: распаковывайте архив целиком. Один `.exe` без `MSFSBuilderCLI.exe` и `_internal` не работает.
- «Мало места» / «Отказано в доступе»: выберите папку на локальном диске с правами записи; OneDrive-папки с включённой синхронизацией могут держать файлы занятыми.

## Что приложить к сообщению об ошибке

Версия программы и Blender, имя и версия пакета, режимы сборки, код причины из диагностики, текст ошибки из «Журнала», точные имена объектов и шаги воспроизведения. Присылать весь пакет самолёта не нужно.
