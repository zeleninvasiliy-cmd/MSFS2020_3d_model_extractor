# Rule Editors

## English version

The graphical rule editor covers skin split, spatial split, mirror, placement, collection override and pivot preservation. Object and joint choices come from the actual glTF/checkpoint, and the form calls the shared CLI validator before saving.

The texture table is on the Textures tab. It shows map state and material, searches installed packages for candidates and stores replacements by the original glTF map name. Rules are applied in the saved order. No direct JSON editing is required for these operations.

Графическое редактирование правил сборки без правки JSON. Появилось на этапе D (версия 1.2.1) и закрывает пункты 7 и 17 списка [Known Issues](Known-Issues).

Два окна:

| Окно | Открывается | Что редактирует |
|---|---|---|
| **Правила редактирования** | «3. Геометрия» → кнопка «Правила редактирования...» | `split_by_skin`, `split_spatial`, `mirror_objects`, `placements`, `collection_overrides`, `manual_keep_pivots` |
| **Таблица карт** | «4. Текстуры» → кнопка «Таблица карт...» | `texture_overrides`, дополнение `extra_texture_dirs` |

Оба окна работают только при открытом проекте и блокируются на время сборки. Изменения попадают в конфиг проекта и применяются к **следующей** сборке; уже собранный `.blend` они не переписывают. Сохраните проект (Ctrl+S), чтобы правила не потерялись.

## Окно правил

Сверху — список «Тип правила» и кнопка **«Прочитать объекты из checkpoint»**. Под ними пояснение к выбранному типу, таблица правил и кнопки «Добавить...», «Изменить...», «Удалить», «Выше», «Ниже», «Проверить все правила», «Закрыть». Двойной клик по строке открывает её форму. Внизу — счётчик правил по всем шести типам.

Список объектов берётся из дерева вкладки «Геометрия». Если дерево пустое, нажмите «Прочитать объекты из checkpoint»: программа вызовет CLI `objects` на последнем `01_geometry*.blend` и заполнит имена, коллекции, исходные узлы glTF и **мировые границы** объектов. Границы нужны редактору разделения по координатам, исходные узлы — разделению по костям и списку pivot.

Порядок строк важен: правила применяются сверху вниз, поэтому «Выше» и «Ниже» меняют результат, а не только вид таблицы.

### Типы правил

| Тип | Поля формы | Что пишет |
|---|---|---|
| **Разделение по костям** | объект, исходный skin-узел, список частей; в части — имя, кости (список с множественным выбором), коллекция, необязательный pivot | `split_by_skin` |
| **Разделение по координатам** | объект, способ: «По оси (границы)» (ось, границы, имена частей) либо «По областям» (имя остатка и список областей с пределами по x/y/z) | `split_spatial` |
| **Зеркальная копия** | источник, цель, ось отражения | `mirror_objects` |
| **Привязка к якорю** | объект, якорь, смещение по X/Y/Z в метрах | `placements` |
| **Коллекция по шаблону** | шаблон имени (`*` и `?`), путь коллекции через «/» | `collection_overrides` |
| **Сохранить pivot (manual)** | узел glTF | `manual_keep_pivots` |

Имена объектов, узлов и коллекции выбираются из списков, заполненных по реальным данным; вручную вписать значение тоже можно. Числа принимают и точку, и запятую (`0.25` и `0,25`). Пустое поле предела означает «предела нет».

**Разделение по костям.** Кнопка «Загрузить кости из glTF» читает документ JSON glTF или JSON-часть GLB через CLI `bones` и показывает настоящие имена суставов; «Выбрать glTF...» позволяет указать другой файл. Кости, уже назначенные другой части, в списке показаны серым и выбрать их нельзя. Кости, не назначенные ни одной части, остаются в исходном объекте. И каждая часть, и остаток должны быть непустыми — иначе сборка остановится. BIN для этого шага не нужен; он проверяется только при сборке геометрии.

**Разделение по координатам.** В режиме «По оси (границы)» кнопка «Предложить границы» делит известный диапазон объекта на равные части, а список имён результатов автоматически подстраивается под число границ: частей всегда на одну больше. В режиме «По областям» каждая область задаётся именем и пределами хотя бы по одной оси; область открывается отдельной формой.

### Проверка до запуска Blender

Каждое сохранение правила проходит два уровня:

1. **Мгновенные проверки в форме** — пустые поля, нечисловые смещения, одинаковые источник и цель, пустой уровень в пути коллекции, повтор имени части или кости, немонотонные границы.
2. **CLI `validate`** — та же функция `validate_config`, которую использует конвейер. Программа записывает временный конфиг, запускает проверку отдельным процессом и показывает её ответ. Определение «правильного правила» существует в одном месте, поэтому редактор и сборка не могут разойтись.

Пока проверка идёт, кнопка «Сохранить» недоступна. При отказе форма остаётся открытой, а текст ошибки конвейера показывается целиком — например `Ошибка: mirror_objects/1: ось должна быть X, Y или Z.`

Если имя объекта отсутствует в загруженном списке, программа спрашивает подтверждение, а не отказывает: Blender мог добавить суффикс `.001` к повторяющемуся имени (пункт 4 [Known Issues](Known-Issues)). Правило с несуществующим именем остановит сборку.

**«Проверить все правила»** проверяет весь набор разом, показывает число правил по каждому типу и **не** помечает проект изменённым.

## Таблица карт

Окно читает отчёт этапа текстур и показывает одну строку на **базовое имя карты** — так же, как её ищет worker: регистр не важен, `%20` раскодирован, обратные слэши приведены к прямым. Колонки: вид карты (Цвет, COMP, Нормаль, Свечение), имя, состояние, путь, материалы. Строки с проблемами идут первыми; выбранные имя и подробности сохраняются при обновлении таблицы.

Состояния собираются из полей отчёта: `найдена`, `отсутствует`, `не читается`, `кандидатов: N`, `сжатая нормаль BC5S`, `нормаль распакована`, `одинаковое содержимое`, `заменена вручную`. Поля отчёта, ключом которым служит полный путь (нечитаемые изображения, сжатые и распакованные нормали, дубликаты), приводятся к тому же базовому имени, поэтому одна карта не распадается на две строки из-за регистра. Под таблицей — подробности по выбранной карте: материалы, все кандидаты, текст ошибки, путь распакованной нормали и файлы с одинаковым содержимым.

| Кнопка | Действие |
|---|---|
| **Обновить** | перечитать отчёт последней сборки |
| **Заменить...** | выбрать файл изображения и записать его в `texture_overrides` |
| **Выбрать из кандидатов...** | взять один из путей, которые нашла сама программа |
| **Найти в установленных пакетах** | CLI `find-textures` по всем корням пакетов; список найденных файлов |
| **Сбросить замену** | удалить ключ из `texture_overrides` и вернуть автоматический поиск |

В окне поиска кнопка «Использовать выбранный файл» записывает замену, а «Добавить найденные папки в поиск» дописывает каталоги в поле дополнительных папок вкладки «Текстуры» без повторов — тогда карты найдутся сами при следующей сборке.

**Ключ замены — имя карты из glTF, а не имя нового файла.** Если вы выбрали `my_livery/body_albd.png` вместо `BODY_ALBD.PNG`, в конфиг попадёт `"body_albd.png": "<путь к новому файлу>"`. Именно так worker ищет замену, поэтому переименованная копия привязывается к материалу.

Отчёт выбирается по номеру сборки в имени, а не по времени изменения. Итоговый `03_model*.json` содержит только геометрию, поэтому программа берёт `02_textured*.json` **той же сборки**: более новый итоговый отчёт не скрывает карты. Если отчёта текстур нет, окно объясняет, что сначала нужно выполнить «Добавить textures» или «Собрать final».

Замены применяются на этапе `textures`. Чтобы увидеть результат, запустите «Добавить textures» или «Весь цикл» и откройте новый checkpoint.

## Что по-прежнему задаётся в JSON

Расширенный ключ `profile` графического редактора не имеет. `normal_decode` и каталог `converted_normal_dir` выбираются на вкладке «Текстуры», а `repair_skin_roots` и `pose_position` — в параметрах geometry; все они сохраняются вместе с проектом. Остальные ключи программа сохраняет при открытии и сохранении проекта, но менять их можно только в файле конфигурации.

## Проверено

- 33 модульные проверки `tests/test_editors.py` управляют настоящими виджетами Tk и настоящим CLI: сохранение правила, отказ конвейера, предупреждение о неизвестном имени, запятая в числе, порядок строк, предложение границ, открытая область, кости из glTF, занятая кость, ключ замены, объединение строк по базовому имени, сохранение выбора, сброс, поиск по пакетам и сохранение проекта.
- Измерение на реальном checkpoint C152 пользователя: `bones` вернул 5 skin-узлов без запуска Blender, `objects` — 257 объектов с границами, таблица карт показала **103 карты, 33 с проблемами** (70 разрешённых путей, 38 записей о недостающих картах, 46 применённых материалов), `validate` принял 8 правил всех шести типов и замену карты и отклонил ось `W` до запуска Blender.
- Игровые ресурсы в тестах не используются: все фикстуры синтетические.
