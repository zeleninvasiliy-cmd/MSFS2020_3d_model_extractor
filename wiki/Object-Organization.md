# Object Organization

## English version

Objects are kept as separate Blender objects and grouped into meaningful collections so the user can inspect and exclude them. The object tree is read from the actual checkpoint, not guessed from a hard-coded aircraft profile.

Use the graphical object list to include or exclude a group or an individual object. Use split rules for joints or spatial bounds, mirror rules for symmetric parts, placement rules for anchor translation, and collection overrides for scene organization. These operations are validated before Blender runs.

---

Цель — получить модель, где детали разделены и лежат в понятных коллекциях, а не один слитный mesh. Универсальная версия не знает названий конкретного самолёта: классификация эвристическая, исключения и правки задаёт пользователь.

Все правки этой страницы задаются графически — окно «Правила редактирования...» на вкладке «3. Геометрия», см. [Rule Editors](Rule-Editors.md). JSON ниже приведён как справочник формата, а не как способ работы.

## Коллекции

Корневая коллекция `MSFS_AIRCRAFT`, внутри — `<Role>_SOURCE` для каждой модели. Затем `msfs_collections.classify` распределяет объекты по токенам имени и исходной коллекции:

```
00_HIDDEN_TRANSFORMS
01_EXTERIOR/
  01_FUSELAGE_AND_GLAZING
  02_WINGS
  03_TAIL_AND_CONTROL_SURFACES
  04_DOORS
  05_LANDING_GEAR
  06_ENGINE_AND_PROP
  07_LIGHTS
  08_EXTERNAL_DETAILS
02_INTERIOR/
  01_PANEL_AND_RADIO
  02_INSTRUMENTS
  03_CONTROLS
  04_SEATS
  05_INTERIOR_DETAILS
```

`collection_overrides` переопределяет путь по glob-шаблону: `{"*RUDDER*": "01_EXTERIOR/03_TAIL_AND_CONTROL_SURFACES"}`. Пустые сегменты пути отклоняются, циклы в дереве коллекций невозможны.

Группировка **ориентировочная**. Она не доказывает, что объект является нужным рулём или стойкой.

## Исключение объектов

`exclude_objects` — список glob-шаблонов, сравнение без учёта регистра. Удаляется объект и его дочерние узлы рекурсивно.

В GUI это делается галочками в дереве на вкладке «3. Геометрия»: снятая галочка объекта пишет точное имя (экранированное, чтобы `[]*?` в имени не воспринимались как маска), галочка группы переключает все её объекты. Возврат галочки убирает имя из исключений.

Полный каталог объектов сохраняется **до** применения исключений (`object_catalog` с флагом `included`), поэтому удалённые объекты не исчезают из списка и их можно вернуть при следующей сборке. Старые glob-шаблоны, не совпавшие ни с одним объектом, сохраняются — галочка их не отменяет.

Исключения применяются на этапе **geometry**. Правки (split, mirror, placements) выполняются до них, поэтому результат split или ссылку mirror можно безопасно исключить, не ломая само правило.

Не исключайте служебные родительские узлы вслепую: это затронет дочерние детали.

## Разделение по костям: `split_by_skin`

Читает JOINTS/WEIGHTS, назначает вершины частям по доминирующему весу кости, создаёт отдельные mesh-объекты с сохранением мировых координат (точность ≤ 2e-6), UV, индексов материалов и custom normals. Проверяется отсутствие потери граней.

```json
"split_by_skin": [
  {"object": "TAIL", "parts": [
    {"name": "RUDDER", "bones": ["RUDDER"], "collection": "01_EXTERIOR/03_TAIL_AND_CONTROL_SURFACES"},
    {"name": "ELEVATOR", "bones": ["ELEVATOR"]}
  ]}
]
```

Ограничения:

- вершины с активным вторым набором весов `WEIGHTS_1` не разделяются — для таких объектов используйте `split_spatial`;
- вершины без весов и грани, смешивающие группы, отклоняются с пояснением;
- порядок вершин Blender сверяется с порядком glTF после приведения осей; при расхождении разделение не выполняется.

Кости называются по данным пакета. Программа не угадывает семантику. В редакторе они не вводятся вручную: кнопка «Загрузить кости из glTF» читает JSON исходного файла командой `bones` и показывает настоящие имена суставов, а уже назначенные другой части кости недоступны для выбора. Кости, не назначенные ни одной части, остаются в исходном объекте; и каждая часть, и остаток должны быть непустыми.

## Пространственное разделение: `split_spatial`

Два формата.

**Cuts по оси** — числа по возрастанию, имён на один больше:

```json
{"object": "WING", "axis": "X", "cuts": [-1.5, 1.5], "names": ["WING_L", "WING_C", "WING_R"]}
```

**Regions по мировым bounds** — `null` означает отсутствие ограничения:

```json
{"object": "FUSELAGE", "default": "BODY", "regions": [
  {"name": "NOSE", "bounds": {"y": [null, -4.0]}},
  {"name": "TAIL", "bounds": {"y": [4.0, null]}}
]}
```

Грани назначается по центру. Подходит, когда граница определяется координатами, а не костями. После split проверьте, что число треугольников не изменилось.

В редакторе мировые границы выбранного объекта показываются прямо в форме (данные команды `objects`), а кнопка «Предложить границы» делит известный диапазон на равные части. Пустое поле предела означает отсутствие ограничения.

## Зеркалирование: `mirror_objects`

Восстанавливает повреждённую сторону из проверенной пары:

```json
{"source": "WING_RIGHT", "target": "WING_LEFT", "axis": "X"}
```

Копируется mesh источника и отражается относительно **мировой** плоскости симметрии по выбранной оси, а не относительно собственных осей объекта: повёрнутый или смещённый источник иначе остался бы на той же стороне. Отражение запекается в вершины, поэтому у цели остаётся положительный масштаб, а её начало координат переносится на другую сторону. Полигоны разворачиваются (`polygon.flip()`), пользовательские нормали пересчитываются, цель отвязывается от родителя. Материалы копируются вместе с mesh.

**Перед применением убедитесь, что source действительно правильный.** Ось — `X`, `Y` или `Z`, по умолчанию `X`. Оба объекта должны существовать и быть MESH.

UV перестраиваются: координата U инвертируется (`u → 1 − u`), иначе надписи, бортовые номера и асимметричная разметка на восстановленной стороне читались бы наоборот. Плоскость симметрии проходит через начало мировых координат, поэтому объект должен стоять в системе координат самолёта.

## Перемещение: `placements`

```json
"placements": {"RUDDER": {"anchor": "TAIL", "offset_m": [0, 0.3, 0]}}
```

Объект отвязывается от родителя и переносится в **точку anchor** плюс смещение в метрах. Поворот и масштаб остаются собственными: повёрнутый узел стойки или руля больше не наклоняет поставленную в него деталь. Наследуется только положение.

| `hybrid_bake_objects` | цели точечного bake |

## Порядок правок в worker

1. split по костям;
2. пространственный split;
3. mirror;
4. placements;
5. снимок `object_catalog`;
6. cleanup по `exclude_objects` и простановка `included`;
7. скрытие empties, сообщения о проверке для выбранного режима.

Результаты каждой правки попадают в `geometry_fixes` отчёта, удалённые объекты — в `removed_objects`.

## Что остаётся пользователю

Выбрать объекты, кости и границы в [редакторе правил](Rule-Editors.md), подтвердить источник mirror, проверить положение деталей в Blender и сообщить имена проблемных объектов для следующего правила. Имена и кости подставляются из фактических данных, но автомата, который объявляет визуальную правильность, нет: просмотр модели остаётся за пользователем.
