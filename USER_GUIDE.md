# MSFS Model Builder — руководство пользователя (русский)

Версия документации соответствует **1.2.1**. Blender устанавливается отдельно; анимации в текущий цикл не входят.

## 1. Установка

Для готовой версии скачайте Setup или Portable из [GitHub Release](https://github.com/zeleninvasiliy-cmd/MSFS2020_3d_model_extractor/releases/tag/v1.2.1). Python и Inno Setup на компьютере пользователя не нужны. Нужен Blender 5.x с включённым glTF importer и NumPy.

Для запуска исходников нужен Windows, Python 3.13 x64 и установленный Blender:

```powershell
cd "C:\Path\To\msfs-model-builder"
python .\msfs_builder_gui.py
```

## 2. Новый проект

1. Откройте меню **Файлы → Новый проект**.
2. Укажите рабочую папку проекта. Папку можно создать прямо в диалоге выбора пути.
3. Выберите пакет MSFS, папку `Community`, `Official`, распакованный мод или папку конкретного самолёта.
4. Если программа находит несколько вариантов одного имени, выберите нужную запись и ливрею.
5. На вкладке общих настроек укажите Blender и папку результатов. Работа вне открытого проекта недоступна.

Проекты сохраняют настройки, выбранные модели, правила, замены карт и историю вариантов `.blend`. Исходная папка самолёта не изменяется.

## 3. Проверка пакета

Если самолёт отсутствует или отмечен как частично доступный, нажмите **Проверить пакет подробно**. В сообщении будут код причины и действие:

| Код | Значение | Что сделать |
|---|---|---|
| `SUPPORTED_PARTIAL` | доступна только часть моделей | открыть мастер моделей и подтвердить состав |
| `COMMON_RESOURCES_ONLY` | найдены только общие XML/текстуры/звуки | указать пакет самого самолёта |
| `LIVERY_ONLY` | найдена ливрея без модели | добавить базовый пакет самолёта |
| `MISSING_MODEL_CFG` / `INVALID_MODEL_CFG` | нет корректного `model.cfg` | выбрать glTF вручную в мастере |
| `MISSING_BUFFER` | рядом с glTF нет BIN | восстановить исходный пакет |
| `UNRESOLVED_ALIAS` | не найден `base_container` | добавить корень с базовым самолётом |
| `UNSUPPORTED_GLTF_FEATURE` | формат или primitive не поддержан | выбрать другой LOD или сохранить пакет для отдельного разбора |

Индекс пакетов разрешает ссылки ливрей на базовый самолёт. При неоднозначности программа не угадывает, а предлагает выбор.

## 4. Мастер моделей

Для неполного пакета откроется окно с отдельными списками **Exterior** и **Interior**. В строках видны LOD, вершины, треугольники, источник роли, происхождение и наличие BIN. По умолчанию выбраны только роли, объявленные в конфигурации. Роль, предложенная только по имени файла, нужно подтвердить вручную.

После подтверждения состав сохраняется в проекте. Для частичной сборки имя варианта получает суффикс `_partial`.

## 5. Сборка геометрии

На вкладке **Геометрия** выберите режим `draw_mode`, `split_by_skin`, `split_spatial`, зеркалирование и размещение только при необходимости. Нажмите **Собрать геометрию**. Кнопка не переходит на другую вкладку: статус, прогресс, тип ошибки и путь к файлу показываются здесь же.

Каждый режим получает отдельную нумерацию. Повторный запуск не перезаписывает старый результат: создаётся следующий файл в подпапке проекта `blend`. Кнопки **Открыть в Blender** и **Показать в Проводнике** доступны после успешной сборки.

Проверяйте в Blender: левую/правую симметрию, шасси, управляющие поверхности, кабину и лишние объекты. Если нужна коррекция, используйте **Правила редактирования**, а не меняйте исходные файлы MSFS.

## 6. Правила редактирования

Редактор задаёт через списки и кнопки:

- разделение по костям или пространственным границам;
- зеркальную копию с отражением трансформации и UV;
- размещение детали по translation якоря с сохранением её поворота и масштаба;
- перенос объектов в коллекции;
- сохранение pivot и ручное исключение объектов.

Кнопка **Проверить все правила** запускает ту же проверку, что и CLI `validate`, до запуска Blender.

## 7. Текстуры

На вкладке **Текстуры** выберите геометрический checkpoint и нажмите **Добавить текстуры**. Таблица показывает каждую карту, материал, состояние, файл-источник и кандидатов из пакетов MSFS. Замена выбирается кнопкой; ключом остаётся имя карты из glTF, а не имя нового файла.

Если карта отсутствует, сначала запустите поиск по установленным пакетам. DDS-нормали могут потребовать ручной проверки; программа сообщает, если формат нельзя безопасно декодировать.

## 8. CLI и диагностика

```powershell
python .\scripts\msfs_universal.py inventory "C:\Path\To\Aircraft" --deep
python .\scripts\msfs_universal.py catalog --root "D:\MSFS\Packages"
python .\scripts\msfs_universal.py catalog --deep --root "D:\MSFS\Packages"
python .\scripts\msfs_universal.py index --no-cache --root "D:\MSFS\Packages"
python .\scripts\msfs_universal.py models "C:\Path\To\Aircraft"
python .\scripts\msfs_universal.py validate .\project.json
python .\scripts\msfs_universal.py build .\project.json --stage geometry
```

`inventory` проверяет один пакет; `catalog` строит список самолётов, а флаг `--deep` дополнительно проверяет каждый glTF/GLB и BIN до создания проекта. `index` разрешает наследование пакетов, `models` печатает кандидатов ролей, `validate` проверяет конфигурацию без Blender, а `build` запускает этап. В GUI этот же режим называется **Глубокая проверка glTF/BIN**. Полный справочник находится в [wiki/CLI-Reference.md](wiki/CLI-Reference.md).

## 9. Если результат неверен

Сначала проверьте выбранные glTF и происхождение ресурса, затем сравните другой режим сборки. Для смещённой детали используйте placement только по translation якоря; для зеркальной детали — `mirror_objects`; для лишнего объекта снимите его в дереве объектов. Если исходного glTF/BIN нет, программа не сможет восстановить точную геометрию.

Логи этапа находятся в окне **Журнал** и в папке проекта. Не удаляйте checkpoint во время активной сборки: программа сама снимает только устаревшую блокировку.

## 10. Ограничения текущей версии

- Blender нужен отдельно.
- Анимации не импортируются.
- Закрытые или отсутствующие исходники не восстанавливаются.
- Результат всегда проверяет пользователь в Blender.
- Коммерческое использование кода запрещено лицензией без отдельного разрешения.
