# Проверка релиза 1.1.0

Дата: 9 ноября 2026. Среда проверки: Windows x64, Python 3.13.15, Blender 5.2.3 LTS, Inno Setup 7, PyInstaller 6.16.0.

## Что изменено

Реализован Приоритет 1 дорожной карты совместимости: исследование ресурсов вынесено в `scripts/package_resolver.py` без bpy, CLI и GUI показывают код причины и рекомендуемое действие вместо единого «недоступен».

| Область | Поведение 1.0 | Поведение 1.1 |
|---|---|---|
| Диагностика | один флаг доступности, причина только в тексте ошибки | 16 кодов причин, у каждого формулировка и действие; поля `can_build_geometry`, `can_build_textures`, `partial`, `needs_model_selection`, `missing_resources`, `candidates`, `dependencies` |
| Глубина проверки | только наличие объявленных файлов | быстрый режим для каталога и `--deep` с разбором glTF: BIN, GLB, несколько buffers, data URI, sparse, Draco, не-треугольные primitives |
| Частичные пакеты | блокировались целиком | подтверждаемая частичная сборка через штатное поле `models`, суффикс `_partial` в имени варианта |
| Пакеты без model.cfg | блокировались | предлагаются найденные LOD glTF (`origin=scan`) и модели из соседних `model.*` для недостающей роли; назначение подтверждает пользователь |
| Ливреи и заглушки | `aircraft_folders` бросал ошибку, скан каталога падал | папка под `SimObjects/Airplanes` считается самолётом и получает код `LIVERY_ONLY`, `COMMON_RESOURCES_ONLY` или `NO_MODEL_FOLDER` |
| Ошибка сканирования | `inventory_error`, запись без объяснения | `SCAN_FAILED`/`PACKAGE_NOT_FOUND` с текстом ошибки в `detail` |
| Отказ выбора моделей | голое сообщение об ошибке | блок «Диагностика пакета» с кодом, действием, недостающими ресурсами и доступными моделями |
| Детали в GUI | сырой JSON в поле деталей | структурированный читаемый отчёт по вариантам, моделям, BIN, LOD и зависимостям |
| Версия | дублировалась в `app_support.py` и файле `VERSION` | `app_support.VERSION` читает поставляемый `VERSION` |
| Имя частичной сборки | суффикс `_partial` терялся при смене режима и перед запуском сборки | суффикс вычисляется в одном месте (`_sync_build_variant`) и сохраняется в имени checkpoint и отчёте; регрессия проверена тестом |
| Перенос источника | частичный состав принимался молча | требуется то же явное подтверждение, что и при создании проекта |

## Измеренный результат

Скан установленного MSFS 2020: 234 самолёта, 2.2 с (повторный, прогретый кэш). Заблокировано 178 → 8, доступно 56 → 226, требуют подтверждения состава 170. Все 166 частичных пакетов имеют одинаковую тройку недостающих зависимостей `base_container`/`model`/`model_xml` — это обоснование приоритета 2 (индекс пакетов и граф наследования).

Оставшиеся 8 недоступны по честным причинам: шесть пакетов общих ресурсов без геометрии, заглушка `Asobo_DA62` в `fs-base-history` (только `panel`) и ливрея `RSP_R44_EC-NIK` с неразрешённым `base_container`.

## Ограничения

- Граф наследования между пакетами не построен: `base_container` разрешается только поиском по имени в доступных корнях, циклы и неоднозначность не отслеживаются (Приоритет 2). Снято этапом A — см. дополнение ниже.
- GLB, несколько buffers, data URI, sparse accessors и triangle strip/fan декодируются общим слоем; Draco, points/lines и дополнительные skin-атрибуты остаются ограничениями (Приоритет 4).
- Роль модели, найденной без `model.cfg`, определяется по токенам имени и всегда требует подтверждения пользователя.
- Проверка на другом физическом ПК не проводилась. Цифровой подписи издателя нет.

Релиз по-прежнему не пересобран; артефакты и суммы выше относятся к 1.1.0. Версия будет поднята до 1.2.0 после приёмки пользователем.

Подсказка выполнить `models <путь>` добавлена в блок «Диагностика пакета» при отказе выбора моделей.

Правила мастера: по умолчанию отмечены только строки с ролью, объявленной в `model.cfg`; недоступные файлы показаны с причиной и не отмечаются; при недоступной роли и разрешённой базе мастер дополнительно обходит базовый пакет; подтверждение требует хотя бы один файл, отдельно спрашивает при отсутствии экстерьера, пишет `models`, добавляет суффикс `_partial` и очищает дерево объектов с шаблонами исключений.

Дефекты, найденные при проверке этапа C. Первый — в интерфейсе: идентификаторы строк `ttk.Treeview` начинаются с `I001` в каждом виджете заново, поэтому строки двух ролей перекрывали друг друга в общем словаре и подтверждение возвращало пустой состав; ключ строки теперь `(роль, идентификатор)`. Второй — в данных мастера: колонка LOD показывала позицию файла в цепочке модельного XML, а не номер из имени, поэтому при пропущенном уровне `S1_LOD06.gltf` выводился как «05»; номер разбирается из имени файла, позиция в цепочке осталась запасным значением. Оба найдены прогоном собственного CLI и GUI программы на реальном пакете, регрессионные тесты добавлены.

Проверки этапа C: **96** unit-тестов (25 индекс, 8 конвейер, 24 GUI, 25 resolver, 14 выбор моделей) за 3.5 с, `--self-test` GUI вернул 0, `compileall` без ошибок. Игровые ресурсы в тестах не используются.

Время 0.55–0.59 с на самолёт. Интерьер Pitts S1 Reno — 56 171 вершина и 278 865 треугольников, интерьер Volocity — 145 141 вершина и 169 321 треугольник. Число доступных для сборки записей не изменилось (226): мастер не создаёт исходники и не ослабляет проверки.

Приёмка пользователем не выполнена: состав и числа проверены программой, визуальную проверку собранных Pitts S1 Reno и Volocity делает пользователь в Blender. Фоновый прогон Blender для этапа C не требуется — изменения не затрагивают worker.

## Дополнение: единый слой чтения glTF/GLB

В исходники добавлен `scripts/msfs_gltf.py`. Он используется resolver, подготовкой геометрии, worker и `split_by_skin`, поэтому все эти этапы теперь одинаково читают JSON glTF и GLB version 2. Поддерживаются несколько локальных BIN, embedded data URI и BIN chunks внутри GLB; перед разбором accessors buffers объединяются в один нормализованный буфер с корректным перебазированием `bufferView` offsets. Команда `bones` также использует этот слой.

Намеренно не заявлены как поддержанные режимы: `KHR_draco_mesh_compression`, primitive mode points/lines и дополнительные наборы skin-весов. Sparse accessors и `TRIANGLE_STRIP`/`TRIANGLE_FAN` уже материализуются в обычные атрибуты/triangles. Оставшиеся режимы получают диагностику `UNSUPPORTED_GLTF_FEATURE`, а не превращаются в неясную ошибку Blender.

Проверки подэтапа: **139** тестов через `unittest discover`, `compileall`, `msfs_builder_gui.py --self-test` и `tests/blender_worker_checks.py` под Blender 5.2.3 завершились успешно. Синтетические тесты отдельно покрывают data URI, несколько BIN, валидный GLB, отсутствующий внешний buffer, повреждённый GLB, sparse POSITION и triangle strip.

Релизные EXE/ZIP и контрольные суммы ещё не пересобраны: `release/output` остаётся артефактом 1.1.0 до завершения пользовательской приёмки и следующего этапа совместимости.

## Дополнение: исправление metadata-only команды bones

Пользовательская проверка выявила два связанных окна: `bones` выдавал ошибку для минимального JSON glTF без `buffers`, после чего редактор сообщал «Кости не загружены». Это было следствием слишком строгого использования геометрического загрузчика для шага, которому нужны только `nodes` и `skins`. Добавлена функция `read_document`: для `.gltf` читается JSON без требования BIN, для `.glb` — JSON chunk без загрузки геометрических buffers. Геометрическая сборка по-прежнему использует строгий `load_gltf` и проверяет все buffers.

Полный набор: **139** тестов OK; синтетические тесты `skin_joints` и CLI `bones` покрывают минимальный glTF без BIN, пустой skin, повреждённый JSON и повреждённый GLB.

## Измерение совместимости на текущей установке MSFS

Read-only census по двум обнаруженным корням Packages обработал **2 559 уникальных glTF**. GLB-файлов, sparse accessors, Draco, нескольких buffers и primitive mode кроме triangles не найдено; 2 425 файлов явно содержат mode 4, остальные не содержат mesh primitives. Три bufferless-файла относятся к служебным visual-effect/VFX ресурсам и не являются обычными моделями самолётов. Deep-проверка реального C172 `Cessna172SP_LOD00.gltf` прошла: 303 627 вершин, 1 213 084 треугольника, внешние buffers найдены, `unsupported=[]`.

Это измерение подтверждает, что текущая установка не требует Draco-ветки для релиза 1.2.0; для сторонних модов она остаётся отдельным резервным режимом с явной диагностикой.

## Проверки

- `python -m unittest discover -s tests -p "test_*.py" -v`: 12 регрессионных проверок CLI и рабочего цикла GUI.
- `tests/blender_worker_checks.py`: фоновый Blender импортирует синтетический glTF; проверяются skin/manual, геометрические данные, исключения, mirror, decal и ошибки входных данных.
- Штатный Cap10C: geometry и textures через CLI; повторные geometry и выбранный исходный checkpoint проверяются через GUI.
- Сборка самостоятельных GUI/CLI EXE; запуск EXE без обращения к системному Python; компиляция Inno Setup и проверка установленной копии.

Проверка установленной копии завершилась успешно: тихая установка в отдельный каталог, запуск установленной GUI и CLI, сохранение путей MSFS с кириллицей и Blender через `--configure-only`, удаление тестовой установки. В поставке не обнаружены `.gltf`, `.bin`, `.dds` или `.blend` самолётов. Удаление тестовой установки сохранило пользовательские настройки.

Рендеры и визуальная приёмка моделей не выполнялись: пользователь проверяет форму, комплектность и внешний вид в Blender.

## Ограничения и дальнейшее развитие

- Работа с другим физическим ПК в этой проверке не проводилась. Установленная копия проверяется на текущем ПК в отдельном каталоге; Python поставляется вместе с программой, Blender устанавливается отдельно.
- MSFS 2020, доступные локальные glTF/BIN и triangle primitives. Зашифрованные пакеты, отсутствующие базовые модели и runtime-изображения нельзя восстановить из недоступных исходников.
- Совместимость проверена с Blender 5.2.3. Произвольные версии Blender и сторонние модели требуют проверки.
- Группы объектов определяются эвристикой; автоматическая сборка не доказывает правильное положение каждой детали.
- Продвинутые split, mirror, placements, texture overrides сохранены в движке; полный графический редактор этих правил, встроенный 3D-просмотр и предпросмотр текстур остаются дальнейшими задачами.
- Индикатор показывает занятость и этап, а не точный процент оставшегося времени. Релиз не имеет цифровой подписи издателя.
