# Дорожная карта расширений

Документ фиксирует направление после версии 1.2.0. Порядок может уточняться по результатам реальных пакетов, но новые функции не должны ухудшать диагностируемость и воспроизводимость уже поддержанных сборок.

## Цели верхнего уровня

1. Увеличивать долю штатных самолётов MSFS 2020 и корректно работающих модов, которые можно собрать без ручной правки JSON.
2. Делать каждый отказ объяснимым: программа должна сообщать конкретный недостающий ресурс, выбранный режим и безопасное действие пользователя.
3. Переносить редкие исправления из ручной настройки в проверяемые GUI-инструменты, сохраняя CLI для автоматизации.
4. Не смешивать точное извлечение с приблизительной реконструкцией: резервные эвристики должны быть отдельным явно выбранным режимом и помечаться в отчёте.

## Приоритет 1 — стабильность 1.2.x

Это небольшие изменения, которые не требуют нового формата проекта.

- Приёмка нескольких реальных ливрей из разных типов пакетов через GUI и сохранение обезличенных отчётов.
- Улучшение каталога: поиск по имени, свёрнутые группы ливрей, фильтры доступности, сортировка по причине отказа и число кандидатов в группе.
- Понятные сообщения для отсутствующих BIN, отсутствующей базы, неверного `model.cfg`, повреждённого JSON и недоступного каталога.
- Безопасное повторение сборки: уникальные checkpoint-файлы, журнал выбранного режима и ссылка на результат.
- Регрессионные синтетические fixtures для каждой найденной причины; игровые ресурсы в репозиторий не добавляются.

## Приоритет 2 — совместимость форматов и пакетов (1.3.x)

По текущему срезу установки 2 559 glTF не требуют этих обходов, поэтому они развиваются по реальным запросам, а не блокируют 1.2.0.

- Поддержка дополнительных буферов и GLB с диагностикой каждого внешнего файла.
- Проверяемая обработка sparse accessors и всех допустимых режимов primitive, с отказом до Blender для неподдержанных случаев.
- Детектор Draco/KTX2 и понятное сообщение «требуется компонент/декодер», без тихой подмены геометрии.
- Более полный граф зависимостей: `base_container`, `model.cfg`, `model.xml`, `texture.cfg`, layout и manifest с указанием происхождения каждого ресурса.
- Дедупликация одинаковых имён самолётов из реальных пакетов и `fs-base-history` с объяснением выбранного кандидата.
- Глубокий режим каталога с прогрессом, отменой и итоговой сводкой; быстрый режим остаётся по умолчанию.

## Приоритет 3 — мастер состава и профили сборки (1.3–1.4)

- В мастере моделей: отдельные списки exterior/interior, LOD, число вершин/треугольников, отсутствующие BIN и происхождение файла.
- Сохраняемые профили: выбранные модели, версия пакета, режим skinning/draw, исключения, карта текстур, результат проверки пользователя.
- Сравнение двух сборок из GUI с отличиями состава, режима и отчёта; визуальную проверку по-прежнему выполняет пользователь в Blender.
- Импорт/экспорт профиля в переносимый JSON без абсолютных путей пользователя.

## Приоритет 4 — графические редакторы и удобство (1.4)

- Таблица объектов с группами, поиском, включением/исключением и предварительным просмотром границ.
- Редактирование split/mirror/placement/pivot через списки и кнопки, ранняя валидация до запуска Blender.
- Предпросмотр замены текстур, сравнение разрешения/формата и отчёт о недостающих картах.
- Пакетные операции для нескольких ливрей одной базовой модели.
- Чёткий журнал этапа вместо необходимости разбирать внутренний JSON.

## Приоритет 5 — резервная реконструкция (после точного режима)

Отсутствующие данные можно оценивать по косвенным признакам (текстуры, XML, анимационные узлы, симметрия), но это не должно выглядеть как точный импорт.

- Сначала строится отчёт уверенности: какие части подтверждены, какие только предположены.
- Восстановление допускается только для явно выбранных деталей и сохраняет источник/метод в metadata.
- Для зеркальных деталей можно использовать симметрию и соседние LOD; для материалов — карты и `texture.cfg`.
- Результат получает отдельное имя режима, например `_approx`, и никогда не заменяет точную сборку автоматически.
- Каждый алгоритм получает синтетические тесты на искусственно удалённых данных; отсутствие исходников не обходится скрыто.

## Что сознательно не является ближайшей целью

- Анимации самолётов: по текущему объёму проекта они исключены из пользовательского цикла.
- Встраивание Blender в установщик: Blender остаётся отдельной зависимостью.
- Хранение игровых моделей, текстур и пользовательских `.blend` в GitHub.
- Автоматическое объявление геометрии «правильной» без проверки пользователя.

## Критерии готовности новой функции

Новая возможность принимается только если у неё есть:

1. синтетический тест без MSFS;
2. сообщение об ошибке и безопасный fallback;
3. запись режима и происхождения ресурсов в отчёте;
4. обновление GUI/CLI-документации;
5. проверка `compileall`, `--self-test` и полного набора unittest;
6. отдельная ручная точка проверки в Blender, если функция меняет геометрию.
